# Deployment

## Encryption Key Management

Potluck uses [pg_tde](https://docs.percona.com/pg-tde/) for transparent data encryption. All database tables are encrypted at rest using the `tde_heap` table access method.

### Development (File-Based Keys)

By default, encryption keys are stored in a local file. This is **suitable for development only**:

```bash
# Default setup uses file-based keys
./scripts/setup.sh
```

You'll see a warning:
```
SECURITY WARNING: Using file-based encryption keys
```

The file-based keyring is stored at `/data/db/pg_tde_keyring.per` inside the database container's data volume.

### Production (HashiCorp Vault)

For production, configure [HashiCorp Vault](https://www.vaultproject.io/) as the key provider:

1. **Set up Vault** with a KV v2 secrets engine:
   ```bash
   vault secrets enable -path=secret kv-v2
   ```

2. **Configure Potluck** with Vault credentials:
   ```bash
   # Option 1: Interactive setup
   ./scripts/setup.sh
   # When prompted, enter your Vault URL and token

   # Option 2: Manual configuration in .env
   VAULT_URL=https://vault.example.com:8200
   VAULT_TOKEN=your-vault-token
   VAULT_MOUNT=secret
   ```

3. **Start fresh** (required when switching key providers):
   ```bash
   docker compose down -v
   ./scripts/setup.sh
   ```

### Other Key Management Systems

pg_tde also supports KMIP-compatible KMS providers (AWS KMS, Azure Key Vault, etc.). See the [pg_tde documentation](https://docs.percona.com/pg-tde/global-key-provider-configuration/index.html) for configuration details.

## Docker Compose Profiles

| Profile | Purpose | Usage |
|---------|---------|-------|
| `dev` | Local development (builds images locally) | `COMPOSE_PROFILES=dev docker compose up -d` |
| `prod` | Production (pulls pre-built GHCR images) | `COMPOSE_PROFILES=prod docker compose up -d` |
| `test` | Test runner | `docker compose --profile test run --rm test` |

### GPU Support

**Development:**
```bash
./scripts/setup.sh --gpu
```

**Production:**
Set `POTLUCK_VERSION=gpu` in `.env` to pull the GPU image variant. Uncomment the `deploy.resources.reservations` block in `docker-compose.yml` to pass through the NVIDIA GPU.

## Environment Variables

Key configuration in `.env`:

| Variable | Purpose | Default |
|----------|---------|---------|
| `POSTGRES_USER` | Database user | `potluck` |
| `POSTGRES_PASSWORD` | Database password | Generated by install script |
| `POSTGRES_DB` | Database name | `potluck` |
| `WEB_PORT` | Web UI port | `8000` |
| `WEB_PASSWORD` | Optional web UI password | (disabled) |
| `WEB_SECRET_KEY` | Cookie signing key | Generated by install script |
| `GPU` | Enable GPU for ML models | `false` |
| `REDIS_PORT` | Redis port | `6379` |
| `VAULT_URL` | HashiCorp Vault URL | (file-based keys) |
| `VAULT_TOKEN` | Vault authentication token | (file-based keys) |
